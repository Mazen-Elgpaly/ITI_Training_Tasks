HTML = HyperText Markup Language، وهي لغة وصف (Markup Language) وليست لغة برمجة؛
 يعني أنا مش بستخدمها عشان أعمل منطق وبرمجة زي 
if وloops وحسابات، 
لكن بستخدمها عشان أوصف للمتصفح محتوى صفحة الويب 
وهيكلها ومعنى كل جزء فيها. بكتب العناصر باستخدام Tags زي <h1> للعناوين، و<p> للفقرات، و<img> للصور، والمتصفح
 بيقرأ الـHTML وبيحوّله لصفحة يفهمها المستخدم
. والـHTML هي أساس بناء صفحات الويب، بينما CSS مسؤول عن الشكل والتنسيق، وJavaScript مسؤول عن السلوك والتفاعل والمنطق.


 <html>

ده العنصر الأب لكل صفحة HTML تقريبًا، وكل حاجة في الصفحة بتكون جواه. يعني ببساطة: ده إطار الصفحة كله.

 <head>

ده الجزء اللي فيه معلومات عن الصفحة للمتصفح ومحركات البحث، مش المحتوى اللي المستخدم بيشوفه مباشرة. يعني: إعدادات ومعلومات الصفحة مش جسم الصفحة.

 <body>

ده كل المحتوى اللي المستخدم هيشوفه فعليًا في الصفحة، زي العناوين والصور والجداول والفورم. يعني: هنا محتوى الموقع الحقيقي.

 <header>

بيمثل مقدمة الصفحة أو مقدمة قسم معين، وغالبًا بحط فيه اللوجو أو اسم الموقع والـnavigation. يعني: بداية الصفحة أو القسم.

 <nav>

مخصص لمجموعة روابط التنقل الرئيسية. يعني: المكان اللي بحط فيه روابط التنقل بين أجزاء الموقع أو الصفحة.

 <main>

بيحتوي على المحتوى الأساسي والفريد للصفحة، والمفروض يكون عندي <main> واحد فقط في الصفحة. يعني: ده قلب الصفحة والمحتوى الأساسي.

 <section>

بيقسم المحتوى إلى قسم له موضوع معين، زي About أو Skills أو Contact. يعني: كل جزء مستقل بموضوعه في الصفحة ممكن يبقى Section.

 <footer>

بيمثل نهاية الصفحة أو نهاية قسم، وغالبًا بحط فيه حقوق النشر وبيانات التواصل والروابط. يعني: خاتمة الصفحة.


  Semantic مش بس بيقول "المكان ده شكله إيه"، لكنه بيقول المكان ده معناه إيه.

 <header>

معناه إن ده رأس/مقدمة صفحة أو قسم.

 <nav>

معناه إن المحتوى ده مخصص للتنقل والروابط.

 <main>

معناه إن ده المحتوى الرئيسي للصفحة.

 <section>

معناه إن ده قسم موضوعي من المحتوى.

 <article>

معناه إن ده محتوى مستقل ممكن يكون له معنى لوحده، زي مقال، بوست، خبر أو Project Card. يعني: محتوى مستقل بذاته.

 <aside>

محتوى جانبي مرتبط بالمحتوى الأساسي، لكنه مش جزء أساسي منه. زي Sidebar أو معلومات إضافية.

 <footer>

معناه إن ده الجزء الختامي للصفحة أو القسم.

 <figure>

بيستخدم لمحتوى مستقل زي صورة أو رسم أو Diagram، وغالبًا معاه <figcaption>.

 <figcaption>

وصف أو Caption للمحتوى الموجود داخل <figure>.

 <address>

بيمثل معلومات التواصل الخاصة بصاحب الصفحة أو الجهة، زي Email أو عنوان.

 <details>

بيعمل جزء قابل للفتح والقفل.

 <summary>

العنوان اللي المستخدم بيدوس عليه عشان يفتح <details>.

 <time>

عنصر Semantic مهم ناقص من المطلوب، وبيستخدم للتعبير عن تاريخ أو وقت بشكل مفهوم للمتصفح ومحركات البحث، مثل تاريخ نشر مقال.

 <article>

عنصر أساسي مهم ناقص من المشروع نفسه رغم إنك ممكن تستخدمه في الـProjects أو المقالات.


Head Elements

 <title>

اسم الصفحة اللي بيظهر في Tab المتصفح. يعني: اسم الصفحة في التاب.

 <meta charset="UTF-8">

بيحدد ترميز الأحرف، وUTF-8 بيسمح بعرض العربي والإنجليزي والرموز بشكل صحيح.

 <meta name="viewport">

مهم جدًا للموبايل، وبيخلي الصفحة تتعامل بشكل صحيح مع عرض شاشة الجهاز.

 <meta name="description">

وصف مختصر للصفحة، وممكن تستخدمه محركات البحث.

 <link>

عنصر أساسي ناقص من قائمة العناصر العامة، وبيستخدم لربط موارد خارجية بالصفحة، زي favicon أو CSS. وفي مشروعك هنستخدمه للـfavicon لو حبيت.



Headings

 <h1>

العنوان الرئيسي للصفحة، والمفروض يكون عندك عنوان رئيسي واضح. في مشروعك مثلًا: Mazen's Portfolio.

 <h2>

عناوين الأقسام الرئيسية، زي About وSkills وCourses وContact.

وكمان فيه:

h3 → عنوان فرعي داخل القسم.

h4, h5, h6 → مستويات أعمق من العناوين.

القاعدة المهمة: العناوين مش مجرد طريقة لتكبير الخط؛ هي Hierarchy للمحتوى.



Text Elements

 <p>

Paragraph، يعني فقرة نصية.

 <span>

عنصر Inline عام لتحديد جزء صغير من النص بدون معنى Semantic محدد. يعني بحدد حتة من الكلام بس من غير ما أديها معنى خاص.

 <strong>

بيشير إلى أهمية قوية للنص، مش مجرد تخانة شكلية.

 <em>

بيشير إلى التأكيد أو التشديد على كلمة أو جزء من الكلام.

 <mark>

بيحدد نص مهم أو Highlighted.

 <br>

ينزل للسطر التالي داخل نفس المحتوى.

 <hr>

بيعمل thematic break، يعني فاصل بين موضوعين أو أجزاء مختلفة.



Lists

 <ul>

Unordered List، قائمة بدون ترتيب مهم، وعادة بتظهر بـ bullets.

 <ol>

Ordered List، قائمة الترتيب فيها مهم، وعادة بتظهر بأرقام.

 <li>

عنصر داخل قائمة، ولازم يكون داخل ul أو ol أو بعض أنواع القوائم الأخرى.

مثال التفكير:

ul = القائمة نفسها
li = عنصر داخل القائمة

Links

 <a>

عنصر الرابط.

ممكن تستخدمه للتنقل داخل الصفحة:

href="about"

أو لموقع خارجي:

href="https://example.com"

وممكن تستخدم:

target="_blank"

عشان يفتح الرابط في Tab جديد.

مهم: في الروابط الخارجية اللي بتستخدم target="_blank"، من الأفضل أيضًا استخدام:

rel="noopener noreferrer"

Images

 <img>

لعرض صورة.

وأهم حاجة في مشروعك:

alt

لأنها بتقدم وصف بديل للصورة لو الصورة مش ظهرت، وبتفيد Accessibility.

ملاحظة: <img> من العناصر Void Elements، يعني ملوش Closing Tag.

 Figure

 <figure>

بيجمع محتوى مستقل، زي صورة.

 <figcaption>

وصف للصورة أو المحتوى.

فكر فيها كده:

figure = الصورة + كل ما يخصها
figcaption = وصف الصورة

 Tables

 <table>

الحاوية الأساسية للجدول.

 <caption>

عنوان أو وصف الجدول.

 <thead>

جزء Header الجدول.

 <tbody>

البيانات الأساسية.

 <tfoot>

Footer الجدول، وممكن تحط فيه الإجمالي أو ملخص.

 <tr>

Table Row، صف.

 <th>

Table Header Cell، خلية عنوان.

 <td>

Table Data Cell، خلية بيانات.

 rowspan

بتخلي خلية تمتد على أكثر من Row.

 colspan

بتخلي خلية تمتد على أكثر من Column.

 Forms

 <form>

الحاوية اللي بتجمع عناصر إدخال البيانات.

 <label>

اسم أو وصف لحقل الإدخال، ومهم جدًا تربطه بالـinput.

مثلاً الفكرة:

label for="email"

والـinput:

id="email"

كده الاتنين مربوطين ببعض.

 <input>

عنصر إدخال، ونوعه بيتحدد بـtype.

أنواع المشروع:

* text → نص.
* email → Email.
* tel → رقم هاتف.
* date → تاريخ.
* radio → اختيار واحد من مجموعة.
* checkbox → اختيار مستقل.

أنواع أساسية أخرى:

* number
* password
* url
* file
* search
* submit
* reset

 <textarea>

مساحة نصية كبيرة، مناسبة للرسائل والتعليقات.

 <select>

قائمة اختيارات Dropdown.

 <option>

اختيار داخل <select>.

 <button>

زر، وممكن يكون:

submit

أو:

reset

أو زر عادي:

button



 Form Attributes 

دي مش Elements، دي Attributes

 required

معناه إن الحقل لازم يتملأ قبل إرسال الفورم.

 placeholder

نص إرشادي يظهر داخل الحقل قبل الكتابة.

 id

معرف فريد للعنصر، ومهم جدًا في ربط الـlabel.

 name

اسم البيانات اللي هتتبعت عند إرسال الفورم، ومهم جدًا في التعامل مع Form Data.

 value

القيمة المرتبطة بالعنصر.

 for

موجود في <label> عشان يربطه بالعنصر اللي عنده نفس id.

 <details>

بيخلي السؤال يفتح ويقفل.

 <summary>

السؤال أو العنوان الظاهر قبل فتح التفاصيل.

يعني:

summary = اللي بشوفه وأدوس عليه
details = المحتوى اللي بيتفتح

 Entities

 &copy;

بتظهر علامة حقوق النشر:

©

 &nbsp;

Non-Breaking Space، مسافة لا تسمح للمتصفح بكسر السطر عندها.

لكن ما تستخدمهاش لمجرد تنسيق الصفحة أو عمل مسافات كتير؛ هي ليها استخدامات محددة.

 <article>

للمحتوى المستقل، وخصوصًا مفيد جدًا في Projects أو Blog Posts.

 <aside>

للمحتوى الجانبي أو المعلومات الإضافية.

 <h3> إلى <h6>

عشان تعمل Hierarchy صحيحة للعناوين.

 <time>

للتواريخ والأوقات بشكل Semantic.

 <dl>, <dt>, <dd>

Description List، مناسبة مثلًا لـ:

Term → Definition

أو:

Skill → Description

 <blockquote>

للاقتباسات الطويلة.

 <q>

لاقتباس قصير داخل النص.

 <code>

لعرض جزء من Code.

 <pre>

لعرض نص محافظ على المسافات والأسطر، وغالبًا مع Code.

 <small>

للملاحظات أو النصوص الثانوية.

 <del>

للمحتوى المحذوف.

 <ins>

للمحتوى المضاف.

 <sub>

 <sup>

نص مرتفع مثل x².

 الفرق: Structural vs Semantic


Structural بيجاوب على:

> "الصفحة متقسمة إزاي؟"

Semantic بيجاوب على:

> "الجزء ده معناه إيه؟"

مثلًا:

<div> يقدر يقسم الصفحة، لكن مش بيقول للمحرك الجزء ده إيه.

بينما:

<header> يقول: ده Header.

<nav> يقول: ده Navigation.

<main> يقول: ده المحتوى الأساسي.

<article> يقول: ده محتوى مستقل.

<aside> يقول: دي معلومات جانبية.

<footer> يقول: ده Footer.

وبالتالي Semantic HTML  بيحقق الهيكلة + المعنى في نفس الوقت.

 <div> vs Semantic Elements

 <div>

عنصر Generic، يعني ملوش معنى خاص.


 <section>

لما الجزء نفسه له موضوع واضح.

 <article>

لما المحتوى يقدر يعيش لوحده كمحتوى مستقل.


 <aside>

للمعلومات الجانبية المرتبطة بالمحتوى.


div = مجرد Container
section = قسم له موضوع
article = محتوى مستقل
aside = محتوى جانبي


head = معلومات عن الصفحة
header = مقدمة محتوى الصفحة


 <strong> vs <b>

<strong> = النص له أهمية.

<b> = مجرد لفت انتباه بصري بدون إعطاء أهمية Semantic بنفس معنى strong.

ففي مشروعك استخدام <strong> أفضل لما تكون تقصد الأهمية فعلًا.

 <em> vs <i>

<em> = تأكيد/تشديد معنوي على الكلام.

<i> = نص بصيغة مختلفة أو صوت/مصطلح/مصطلح تقني في بعض السياقات، بدون أن يكون المقصود بالضرورة التأكيد.
